# 股票日报逐期闭环规则

这份文件只规定公开研究报告的工作流程。行情采集由 GitHub Actions 执行，日报任务从 GitHub 读取已验证快照、联网核对新增事实、将公开报告归档并在任务对话交付。

## 一期的输入和输出

1. 固定北京时间报告日期和类型，核验交易日历。读取 `output/latest/manifest.json`，确认 `report_readiness` 属于本期；用 `selected_file` 读取不可变快照。核对日期、类型、时点、字段、来源。只有计算原始字节 SHA-256 并与 Manifest 相等，才写“哈希已验证”。
2. 读取 `reports/latest/manifest.json` 和其中指向的上一份已归档**正文**。优先同日早报→午报→晚报，早报承接最近晚报。不能只读索引，也不能读取本期之后的报告。
3. 将上一期每个仍在观察期内的可检验判断、关键价位、量价条件及失效条件逐项核对。结果标为“兑现、部分兑现、未兑现、待到期、无法验证”，注明实际数据时点和来源。没有证据不得把“待到期”写成兑现。对错误判断说明修正。
4. 选择本期活跃观察池 6—8 只，东威科技 688700 始终在池中。其余优先从 Core 和 Watch 采集池选，可加入经交易所核对上市状态和代码的新增股票。依次考量上一期判断是否仍成立、当期可靠价格和量价、公司公告或产业新证据、同业扩散、可核验的未来条件。逐只记“保留、新增、移出”和理由；失效或证据不足的移出，若判断仍强且未到期可继续保留。无需机械强制轮换。
5. 从活跃池选 3—5 张重点交易卡，必须包含东威。每卡包含数据来源与截至时间、BOLL 优先及 KDJ/MACD 辅助的可用指标、成交量或成交额的**可比口径**、本期判断、下一期或明确期限的验证条件、失效条件。没有可比成交量时仅写绝对量或留空；不能用今日上午与昨日全天比较。
6. 报告第 2 节写上一期逐项验证，第 5 节写活跃观察池及交易卡的增加、保留、移出，第 7 节用紧凑表格写“代码、判断、来源及数据时点、下一验证条件、期限、失效条件、是否重点卡”。第 7 节就是下一期读取的承接状态，不依赖聊天记忆。
7. 归档公开正文并回读正文和索引，核验路径、标题、数据截点和摘要；再在对话交付同一份报告。归档失败也交付报告并说明失败状态。一次任务只处理一期，休市日早午静默，晚报继续。

## 每期一只全市场首选关注股

推荐的前提是本期已对当时A股全市场每只股票完成可核查的实质分析。全量报价、自动指标计算、评分排序或只深查Top30，均不能单独证明已经逐只认真分析。固定Core/Watch池、上一期首选和locked标的不得代替全市场研究。

### 全量范围与逐股证据

1. 以沪、深、北三家交易所截至本期的上市证券名录核对A股范围，保留名单版本、来源、获取时间和代码。ST、停牌、新上市或历史不足股票也必须逐只登记与分析其状态、风险和关注价值，不得先过滤后宣称全量完成。退市证券按名录状态另记，不混入当前上市数量。5000或5222不是固定总数；expected_count必须来自本期核验的名单，不明则记null，禁止用已取到的数量充当应覆盖数量。
2. 每只股票保留独立、可读的分析记录：业务及行业位置；最新可用财报的增长、利润质量、现金流和负债；适合行业的估值及同业比较；公告、催化、政策和主要风险；BOLL为主及KDJ/MACD辅助的价格结构与可比量价；综合关注或暂不关注的理由、反方证据及后续验证条件。每项附来源和真实数据日期，明确事实、推断和缺口。简单套用分数或复制相同评语不算实质分析。
3. 行情、技术、财务、公告分别保留截点及口径。午报禁止混入午后数据；盘中未完成日线不得冒充已完成指标。财报可以是最新已发布报告，不要求每日重新发布；复用历史研究必须本期逐股核对新增公告、财报、除权、上市状态及行情变化，并记录复核时间和结论。抓取失败不等于没有新公告；历史缓存不等于本期复核完成。
4. 逐股记录按期存到`reports/research/YYYY/MM/DD/{early|noon|evening}/`并可分片，配套`coverage.json`记录上市名录路径/版本、各交易所数量、expected_count、reviewed_count、complete_count、incomplete_count、missing_codes、duplicate_codes、数据截点、分析口径和逐股文件路径。条件明确的不关注结论仍是分析；缺关键证据的股票标为incomplete，不得当成完成。正文给覆盖摘要和可打开的证据索引，不需堆入5000多条正文。
5. 发布首选前实际核对名录与逐股代码集合：每只当前上市A股恰有一条已完成实质分析的记录，`complete_count == expected_count`、未分析与缺关键证据数量均为0，所有记录均符合本期截点；并由本期研究执行者逐一审阅和综合判断。只检查数量相等、检查几个样本、算法输出或模型自报“已审阅”不能证明完整性。保存完成及审阅证据，不可凭字段值自证认真分析。

### 首选与交付

- 完成上述前提后，横向比较全量逐股结论，深度复核领先候选及反方证据，只选择一只。第1节写“本期全市场首选关注：名称（代码）”，同时写应覆盖/完成分析数量、研究截点和证据索引；第5节说明胜出理由及其他主要候选的弱点，给完整重点卡；第7节保留承接状态。
- 重点卡含真实行情/资讯截点、当前状态、核心理由、主要1—3个交易日窗口、若则触发条件、失效条件；必要时另写2—8周逻辑。最值得关注不等于立即买入，可靠证据不足时不得编造行情、指标或精确价位。
- 任一股票未完成分析、名单不完整、关键证据缺失或逐股审阅未完成时，写“本期全市场逐股分析未完成，暂无符合该标准的推荐股”，公开实际完成数量与缺口；不得把小范围候选、MA5候选或固定观察池首位改称全市场推荐，也不得沿用上一首选凑数。七节报告仍照常交付，可展示现有观察池研究，并明确其研究范围。
- 首选可连续保留，但每期仍要完成全量复核，核验上一首选的兑现、期限和失效条件；更换说明旧股变化及新股胜出原因，不机械轮换。有效首选纳入本期6—8只活跃池及3—5张重点卡；东威仍按既有规则研究，locked不构成首选依据。
- 公开索引保留既有记录和字段，增加`focus_stock_code`、`focus_status`和`full_market_review`。后者记录expected_count、reviewed_count、complete_count、incomplete_count、coverage_file和market_cutoff。未达到全量逐股标准时`focus_stock_code=null`、`focus_status=full_market_analysis_incomplete`；全部完成但未找到合适标的时为`no_qualified_candidate`，不得误写分析未完成。旧报告不改写为已经满足新标准。

## 数据状态和恢复

- `ready_a`：仍需核对目标时点、技术口径及市场来源，不自动意味着报告每个字段都可靠。
- `ready_b`：明确缺口；只对确有缺口的段落降低置信度，能从权威来源同一时点补齐的字段逐项补齐。
- `not_ready`、旧日期、错误时序、哈希不符：拒用该快照；最多重试一次，然后直接查交易所、公司公告和可靠行情源。标明外部来源、时间与尚缺字段；不能拿后来行情填较早的报告。
- GitHub 定时任务可能排队或漏触发。延迟采集按真实启动时段生成`delayed-current-phase`数据；每次运行另检查当日午间快照，缺失或损坏时只从完整分钟历史恢复11:30数据，标记`historical_point_in_time_recovery`和`point_in_time_recovered=true`。不能用午后报价、高低价、宽度或板块榜倒填午间。事后恢复数据不等于曾在12:40前可用，也不补发或改写已交付报告。日报任务照常交付可核验内容，不把“无法完整验证”写成没有机会或没有风险。
- 公开仓库不保存持仓、成本、账户、个人交易记录、私人任务提示词和原始对话。不执行自动交易。
