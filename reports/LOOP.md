# 股票日报逐期闭环规则

这份文件只规定公开研究报告的工作流程。行情采集由 GitHub Actions 执行，日报任务从 GitHub 读取已验证快照、联网核对新增事实、将公开报告归档并在任务对话交付。

## 一期的输入和输出

1. 固定北京时间报告日期和类型，核验交易日历。读取 `output/latest/manifest.json`，确认 `report_readiness` 属于本期；用 `selected_file` 读取不可变快照。核对日期、类型、时点、字段、来源。只有计算原始字节 SHA-256 并与 Manifest 相等，才写“哈希已验证”。
2. 读取 `reports/latest/manifest.json` 和其中指向的上一份已归档**正文**。优先同日早报→午报→晚报，早报承接最近晚报。不能只读索引，也不能读取本期之后的报告。
3. 将上一期每个仍在观察期内的可检验判断、关键价位、量价条件及失效条件逐项核对。结果标为“兑现、部分兑现、未兑现、待到期、无法验证”，注明实际数据时点和来源。没有证据不得把“待到期”写成兑现。对错误判断说明修正。
4. 选择本期活跃观察池 6—8 只，东威科技 688700 始终在池中。其余优先从 Core 和 Watch 采集池选，可加入经交易所核对上市状态和代码的新增股票。依次考量上一期判断是否仍成立、当期可靠价格和量价、公司公告或产业新证据、同业扩散、可核验的未来条件。逐只记“保留、新增、移出”和理由；失效或证据不足的移出，若判断仍强且未到期可继续保留。无需机械强制轮换。
5. 从活跃池选 3—5 张重点交易卡，必须包含东威。每卡包含数据来源与截至时间、BOLL 优先及 KDJ/MACD 辅助的可用指标、成交量或成交额的**可比口径**、本期判断、下一期或明确期限的验证条件、失效条件。没有可比成交量时仅写绝对量或留空；不能用今日上午与昨日全天比较。
6. 报告第 2 节写上一期逐项验证，第 5 节写活跃观察池及交易卡的增加、保留、移出，第 7 节用紧凑表格写“代码、判断、来源及数据时点、下一验证条件、期限、失效条件、是否重点卡”。第 7 节就是下一期读取的承接状态，不依赖聊天记忆。
7. 归档公开正文并回读正文和索引，核验路径、标题、数据截点和摘要；再在对话交付同一份报告。归档失败也交付报告并说明失败状态。一次任务只处理一期，休市日早午静默，晚报继续。

## 数据状态和恢复

- `ready_a`：仍需核对目标时点、技术口径及市场来源，不自动意味着报告每个字段都可靠。
- `ready_b`：明确缺口；只对确有缺口的段落降低置信度，能从权威来源同一时点补齐的字段逐项补齐。
- `not_ready`、旧日期、错误时序、哈希不符：拒用该快照；最多重试一次，然后直接查交易所、公司公告和可靠行情源。标明外部来源、时间与尚缺字段；不能拿后来行情填较早的报告。
- GitHub 定时任务可能排队或漏触发。晚于报告窗口的任务会记为 `skipped_expired`，不重新标记日期。日报任务照常交付可核验内容，不把“无法完整验证”写成没有机会或没有风险。
- 公开仓库不保存持仓、成本、账户、个人交易记录、私人任务提示词和原始对话。不执行自动交易。
