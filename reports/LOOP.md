本规则规定公开研究报告的流程。行情采集和全市场技术初筛由 GitHub Actions 执行；日报直接读取快照和筛选结果，核验当期事实、比较候选、交付正文并归档。2026-10-15 起选股范围改为当期交易所官方沪深普通 A 股，主板、创业板、科创板均纳入，排除北交所、B 股和 CDR。逐股基础深研完成率不作为推荐门槛，历史报告保持原样。

## 一期的输入和输出

1. 固定北京时间日期和类型，按交易所日历核验交易日。读取 `output/latest/manifest.json` 及本期 `report_readiness.selected_file` 不可变快照；核对日期、类型、来源、单位与时点。只有实际计算原始字节 SHA-256 并匹配 Manifest 才写哈希已验证。
2. 优先读取 `reports/latest/handoff.json` 的小型入口和上一期实际归档正文。早报承接最近晚报，午报承接当日早报，晚报承接同日早午报；不能只看索引或读取后期报告。入口缺失或落后时直接读取目标期次的确定路径，不能因此跳过当期。完整历史仍保存在 `reports/latest/manifest.json`，不在每期手工读取、重写整个历史索引。
   另读 `output/boll/latest/manifest.json`、`latest_screen.selected_file` 和 `candidate_file`，核对官方名录日期/数量、完成日线日期、代码集合、有效技术数/剔除数/未解决数及 `technical_screen_complete`。午报使用当日 `latest_noon_overlay`，核对 `collection_details.noon_comparison` 的全量比较记录和 `noon_candidates.json`，不能被午后的 `latest_overlay` 取代。详见 `docs/boll-screen.md`。
3. 逐项验证前期判断、量价、关键价位、原窗口与失效条件，标为兑现、部分兑现、未兑现、待到期或无法验证，注明来源及实际时点；对错误判断作修正，不放宽失效门槛。
4. 选择活跃池 6—8 只，东威科技 688700 始终在池；其余优先从当期全市场筛选入围候选中动态选择。Core/Watch 仅作固定跟踪来源，不能限制推荐范围。根据前期验证、当期价量、新公告与产业证据、同业表现和风险记保留/新增/移出，不机械轮换。
5. 选择 3—5 张重点条件卡，东威必有。每卡包含来源、BOLL 与辅助指标、可比量价、判断、触发、期限与失效条件。固定研究标的不自动成为推荐。
6. 第 1 节分别点名综合首选 A 和技术首选 B；每类至少比较 3 个候选。双重首选须明示并列技术次选，不机械凑两只。第 5 节写横向比较和条件，第 7 节写代码、卡、判断、下一验证、原窗口、失效及来源时点。承接以正文为准。
7. 形成完整七节正文，直接在任务绑定的对话交付一条 final。依赖失败最多重试一次后换可靠源；无法补齐的字段列缺口。归档失败仍交付正文。不得只交链接或进度。
8. 按北京时间日期和类型去重，只有实际可见完整聊天正文算已交付，归档或触发成功不算。目标正文已归档但尚未聊天交付时，读取并交付同版；不要重复上传。

## 当期候选比较与双首选

- 日报直接读取已保存的全市场技术筛选并完成候选必要研究，不恢复已停用的持续研究任务、不读取其检查点或旧基础研究完成率。批量采集、缓存及失败续跑在 GitHub Actions 执行，日报不从零下载数千只历史数据，不因采集缺口延迟正文。
- 比较市场主线和竞争方向，区分短线、2—8周、6—24个月。事实注明当期可靠来源和发布时间，区分事实、推断、假设。候选范围据实际读取披露，不把采集池当全市场，不声称未经执行的全市场筛选或最优结论。
- BOLL 为主，KDJ/MACD 为辅。先观察收口/开口、中轨方向、沿上轨趋势及回踩承接；KDJ 采用相对位置、J 上穿/下穿，不机械套用 20/80。上升趋势收盘跌破中轨且两个完成交易日未收回，按既有条件判弱；不能下移旧失效位以延续判断。
- 全市场技术初筛后，先看前 10—20 只的已计算摘要，再补查相关候选的公告、业绩、现金流、估值、主线和空间。综合首选与技术首选每类至少比较 3 只；技术首选以价格结构和可比量价为主，不能直接等同技术得分第一。必须复核布林窗口及预计持有期权益事件；列胜出理由、其他候选不足、时点、条件、当前状态、原窗口、反证和失效位。
- 条件未触发仍可确定首选，明确等待条件，不能写成立即买入。推荐可沿用也可更换，必须说明证据；固定跟踪不等于固定推荐。
- 不以全部公司基础档案/深研未完成阻止推荐。技术筛选有真实缺口时，按时交付已核验范围内的暂选，明确“部分筛选暂选，等待条件”及实际范围，不能称已完成全市场筛选，也不能无说明退回原观察池。若可靠候选全部不可交易或最低关键证据缺失，说明具体原因，不编造股票、价格、新闻或胜率。
- 综合首选字段为 `focus_stock_code`/`focus_status`，技术首选为 `technical_stock_code`/`technical_status`；状态限 `entry_condition_met`、`watch_for_trigger` 或 `data_unavailable`，方法为 `market_event_technical_dual_pick_v1`，保留实际筛选版本和覆盖。历史正文不追溯改写。

## 数据状态和恢复

- `ready_a` 仍须核对目标时点、技术口径及来源，不代表全部字段自动可信。
- `ready_b` 明确必要缺口，能从同一时点的可靠来源补齐则补齐。
- `not_ready`、旧日期、时间倒置或哈希不符拒用；最多重试一次后直接查交易所、公司公告和可靠行情源。不得用后来行情倒填早期截点。
- 早报行情使用最近完成交易日，资讯截至 09:00；午报行情严格 11:30，资讯 12:40；晚报当日收盘、资讯 21:00。休市日标注实际历史行情日期。
- BOLL(20,2,ddof=0)、KDJ(9,3,3，K/D 初值 50)、MACD(12,26,9，双倍柱)只用完成日线，注明参数、复权、单位及指标日期。未实际复算不能冒充更新，不宣称与其他软件完全一致。
- 午间量额只与上日同一完整上午比较，缺基线只列绝对量额；市场宽度和成交额说明沪深/媒体统计范围。
- 历史时点重建保留原截点并标注事后恢复，不能以午后值倒填午间。数据缺口不阻塞其余可靠内容的交付。

## 调度、归档与聊天交付

交易日北京时间 09:00、12:40、21:00；休市日早午静默、晚报继续。使用计划启动时点确定本期，提前最多 5 分钟、延迟不足 60 分钟可执行；合法启动后不能因研究结束较晚取消正文。常规不补过期报告、不增加尾盘提示。明确人工补发或发送验收按其指定要求执行。

仅公开归档公开行情研究、直接来源与无隐私承接摘要。不得上传个人持仓、成本、账户、交易记录、私人提示词、凭据或原始对话，不执行自动交易，不修改采集代码/配置/工作流。

归档路径为 `reports/archive/YYYY/MM/DD/{early|noon|evening}.md`。同版幂等，明确 404 才新建；不同版另存 revision。报告端最多尝试一次正文归档后立即 final，不等待索引和来源大文件上传。`report_support.index` 及 `Maintain public report index` 工作流自动补齐索引并生成小型 `handoff.json`，保留完整历史、其他期次和已有字段。可选 `*-handoff.json` 公开元数据必须绑定正文 SHA-256。没有平台运行结果时，归档的聊天交付状态始终是 `unverified`。

- 现有午间扫描任务兼任交付核验：09:30、13:10、21:30核对对应主任务的 `scheduled_for`、`run_id` 和 `latest_result`。早报结果不能抵午报。主任务仍运行时不并发重跑；已记录当期正文时不自动重发；`no_update`、失败或只有摘要时读取同版完整归档并在核验任务 final 全文补发。无正文才按原截点有界恢复，不能混入后来事实。

- 核验任务按本次运行的 `scheduled_for` 固定分支，并用真实北京时间检查是否到点。提前最多5分钟时分段等待到计划时刻（单次不超过60秒），再执行同一分支；异常提前更多时明确调度异常，不把提前检查写成采集失败。`report_support.delivery.assess_verifier_run` 提供此判断；延迟至12:20后只读已有验收，不重抓午后报价。12:40前午报尚未生成应标“未到期”，与午间数据状态分开。

- 同一完成交易日重扫时，`market_screen.completed` 只允许复用此前已验收的“该日无成交”剔除：屏幕、记录分片和原始行情字节哈希均须一致，原始字段重新解析且与该日零量额记录一致。仅修复 `missing_target_session_bar`，不借用其他日期、不填造日线、不替代当前行情，也不推断今天停牌。

- 部署后的真实失败样本通过 `market_screen.noon_probe` 补充回放；其实际恢复时间、原失败状态和原件保留，不回写午报原截点的可用性，不替换 `noon_update.json`、历史推荐或正文。并发发布只合并对应指针，拒绝覆盖已提交的不可变证据。
