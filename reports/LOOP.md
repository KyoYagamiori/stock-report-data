# 股票日报逐期闭环规则

这份文件只规定公开研究报告的工作流程。行情采集由 GitHub Actions 执行，日报任务从 GitHub 读取已验证快照、联网核对新增事实、将公开报告归档并在任务对话交付。

## 一期的输入和输出

1. 固定北京时间报告日期和类型，核验交易日历。读取 `output/latest/manifest.json`，确认 `report_readiness` 属于本期；用 `selected_file` 读取不可变快照。核对日期、类型、时点、字段、来源。只有计算原始字节 SHA-256 并与 Manifest 相等，才写“哈希已验证”。
2. 读取 `reports/latest/manifest.json` 和其中指向的上一份已归档**正文**。优先同日早报→午报→晚报，早报承接最近晚报。不能只读索引，也不能读取本期之后的报告。
3. 将上一期每个仍在观察期内的可检验判断、关键价位、量价条件及失效条件逐项核对。结果标为“兑现、部分兑现、未兑现、待到期、无法验证”，注明实际数据时点和来源。没有证据不得把“待到期”写成兑现。对错误判断说明修正。
4. 选择本期活跃观察池 6—8 只，东威科技 688700 始终在池中。其余优先从 Core 和 Watch 采集池选，可加入经交易所核对上市状态和代码的新增股票。依次考量上一期判断是否仍成立、当期可靠价格和量价、公司公告或产业新证据、同业扩散、可核验的未来条件。逐只记“保留、新增、移出”和理由；失效或证据不足的移出，若判断仍强且未到期可继续保留。无需机械强制轮换。
5. 从活跃池选 3—5 张重点交易卡，必须包含东威。每卡包含数据来源与截至时间、BOLL 优先及 KDJ/MACD 辅助的可用指标、成交量或成交额的**可比口径**、本期判断、下一期或明确期限的验证条件、失效条件。没有可比成交量时仅写绝对量或留空；不能用今日上午与昨日全天比较。
6. 报告第 2 节写上一期逐项验证，第 5 节写活跃观察池及交易卡的增加、保留、移出，第 7 节用紧凑表格写“代码、判断、来源及数据时点、下一验证条件、期限、失效条件、是否重点卡”。第 7 节就是下一期读取的承接状态，不依赖聊天记忆。
7. 归档公开正文并回读正文和索引，核验路径、标题、数据截点和摘要；再在对话交付同一份报告。归档失败也交付报告并说明失败状态。一次任务只处理一期，休市日早午静默，晚报继续。

## 全市场筛选、候选深研与重点推荐（2026-10-14）

研究分为三个层次：每日全市场筛选、每日优先深研约10—20只候选、跨周期滚动基础档案。推荐前提是可核查的每日全市场筛选完成，以及最终入选公司的深研与当期复核合格；全部公司的基础深研完成数不再是日报推荐的前置条件。自动筛选与公司深研不能混称，报告按原时间交付，不等待后台扩展研究。

### 每日筛选
- 以沪、深交易所当期名录核对沪深A股，北交所剔除；数量不硬编码。保存来源、名单版本、获取时间及代码集合。ST、停牌、新股、历史不足逐码保存状态和排除依据，不静默漏股。
- 使用最近完成交易日价量、BOLL(20,2,ddof=0)、KDJ(9,3,3)、MACD(12,26,9)及可核验公告/权益风险标记。BOLL为主，其他指标辅助，不用MA5排名替代。保留逐码来源、实际数据日期、参数、复权、单位、可计算状态与缺口。
- 名录与逐码记录无漏无重；每股有真实可计算指标或有证据的不可计算/不可交易原因才算范围覆盖。请求失败仍是未完成。报价全覆盖、某日旧排名或只有606只技术资料不能声称当前全市场指标筛选完成。
- 筛选分批保存，发布回读验收后登记完整版本。午报和晚报读取当天已保存版本并做候选、主线及公告增量复核；如只有局部增量，明确范围，不称目标时点全市场复核完成。报告分别标明全市场筛选的完成日线日期、当期候选行情及资讯截点。

### 候选深研与档案
- 每日优先约10—20只，以新公告/财报、主线、技术承接和证据缺口安排；这是研究目标，不是保证完成数量。筛选候选不能自动计为深研。
- 深研仍须实际审阅业务竞争；最新财报增长、利润质量、现金流、负债；行业适用估值与同业；公告、权益、催化风险；BOLL和可比量价；综合判断、反方证据、验证条件及期限。所有事实注明来源和日期，缺口明确。
- 基础档案首次分批建立，财报或重大变化更新，完整审阅跨报告累计；无变化的历史财报不重复从头研究。最终入选必须按本期截点核对新增财报/公告、权益/上市停牌、价量与旧判断变化；失败不能写成无新风险。
- 逐股来源与审阅保留版本并回读。research_pipeline/ledger.py只用于基础深研结构/版本验收，其旧full_market_analysis_incomplete字段不能作为新规则推荐的唯一门槛。

### 推荐与披露
- 通过每日筛选范围验收及入选公司本期深研验收后，横向比较领先候选，最多给一只“全市场筛选后的重点推荐”。说明筛选日期/范围、候选核验截点、胜出理由、1—3交易日窗口、BOLL及量价、若则条件、失效条件和反方证据。不称为全市场逐股深研后的最佳股票。
- 没有合格标的可以无推荐；筛选未完成、候选深研未合格分别说明。允许给已核验范围内的条件关注，明确它与正式推荐的区别。locked东威保持固定研究，不能默认首选。
- 正文和索引分别登记market_screen、candidate_review、research_baseline；展示名录数、筛选覆盖/有效指标/未完成数量及日期、当期增量范围、候选深研/复核数、累计完整基础及新增数。未知用null，历史full_market_review保留原口径与数字。
- focus_status采用screening_or_candidate_review_incomplete、no_qualified_candidate或screened_candidate_verified；未过新验收focus_stock_code=null。旧报告不追溯改写，新增筛选、研究或更正另存版本。

## 数据状态和恢复

- `ready_a`：仍需核对目标时点、技术口径及市场来源，不自动意味着报告每个字段都可靠。
- `ready_b`：明确缺口；只对确有缺口的段落降低置信度，能从权威来源同一时点补齐的字段逐项补齐。
- `not_ready`、旧日期、错误时序、哈希不符：拒用该快照；最多重试一次，然后直接查交易所、公司公告和可靠行情源。标明外部来源、时间与尚缺字段；不能拿后来行情填较早的报告。
- GitHub 定时任务可能排队或漏触发。延迟采集按真实启动时段生成`delayed-current-phase`数据；每次运行另检查当日午间快照，缺失或损坏时只从完整分钟历史恢复11:30数据，标记`historical_point_in_time_recovery`和`point_in_time_recovered=true`。不能用午后报价、高低价、宽度或板块榜倒填午间。事后恢复数据不等于曾在12:40前可用，也不补发或改写已交付报告。日报任务照常交付可核验内容，不把“无法完整验证”写成没有机会或没有风险。
- 公开仓库不保存持仓、成本、账户、个人交易记录、私人任务提示词和原始对话。不执行自动交易。

## 研究检查点与交付
读取reports/research/CONTINUOUS.md、reports/research/state/worker.json及其引用的名录、资料、筛选和实际review。持续研究负责每日筛选、候选优先深研及基础档案；日报负责本期候选复核、七节正文、公开归档及对话交付。基础未完成不挂起日报，任务触发或配置成功不等于研究完成。
日报的本期证据写独立日期周期目录，不写worker.json、不改持续研究不可变文件。持续研究先上传不可变资料回读，再以最新blob SHA增量合并worker，保留别的运行和所有历史记录。
结构化财务核对页集合、行数与代码交集，日线逐碼汇总真实保存记录，排除未完成当日日线。资料采集、筛选、深研、本期复核分别验收，不由自动状态或模板评语凑完成数。
人工明确补发时交付目标时点版本，不能加入目标截点之后的行情或资讯；定时任务仍不自动补发过期报告。归档与聊天交付分别验收，全文必须在本期对话直接可见。
