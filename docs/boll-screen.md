# 沪深全市场布林筛选

日报先读取 `output/boll/latest/manifest.json`，再读其中 `latest_screen.selected_file`
和 `candidate_file`。若有当日 `latest_overlay`，午报另读该文件核对 11:30 行情。
实际归档文件、日期、计数、缺口和参数决定可用性；Actions 成功或候选分数不能
代替这些校验。

## 数据与筛选

- 名录来自上交所主板/科创板和深交所官方 A 股列表，校验分页、总数、代码集合，
  包含创业板 302 代码；排除北交所、B 股和 CDR。当前名录与最近完成交易日的
  行情日期分别保存，新上市但在行情目标日尚未上市的股票单独登记。
- 日线统一未复权，保存最近 180 根原始 OHLCV，指标只计算最后 160 根完成日线。
  BOLL(20,2,ddof=0)、KDJ(9,3,3，K/D 初值 50)、MACD(12,26,9，双倍柱)。
  不宣称与同花顺完全一致。
- BOLL 排序重点是向上趋势回踩中轨、收口后向上开口、沿上轨上行。布林最多
  70 分，量/流动性最多 20 分，KDJ/MACD 最多 10 分；这是透明的研究优先级，
  尚未作历史胜率检验。流动性门槛用 `收盘价×成交股数` 的估算代理，明确不是
  交易所成交额，不能据此宣称真实资金流入。
- ST/退市风险名称、目标日尚未上市、确有证据的目标日无成交、新股历史不足
  等按逐只理由剔除。请求失败、来源不明的历史截断、目标日缺线仍是未解决缺口，
  不计为筛选完成。所有官方代码必须有且仅有一条记录。
- 若确因发行人公告停牌而没有目标日日线，可用 `config/boll_trading_states.json`
  中逐只读过公告的日期限定证据登记剔除；保存原文来源与实际核验时间，未下载
  原始字节时 SHA-256 留空。仅在明确核验的交易日生效，不能自动延长到下一日；
  如出现目标日成交与停牌证据矛盾，恢复为未解决冲突。
- 技术筛选通过只产生约 20 只研究候选。日报再核验近期公告/权益分派、业绩、
  现金流、行业催化、估值及可执行入场条件，横向比较后选唯一一只首选。
  技术分第一名不是自动买入指令，也不是已完成基本面研究。

## 增量与调度

首次补齐历史后，GitHub Actions 缓存逐股日线；缓存丢失时使用有哈希的公开
bootstrap 种子继续。每个交易日 15:45 的全量收盘行情，可在缓存正好截至上一
交易日、价格基准未重置时追加一根日线。缺日、分红/拆股导致的昨收重置或校验
失败会回到该股的历史接口补齐，不将不同复权口径拼接。

08:20 更新官方名录并复用最近完成日线供早报；11:32 全市场行情快扫供午报；
15:45 更新日线供晚报。日报原发送时间不变。数据采集在 GitHub Actions 内完成，
不恢复独立的 ChatGPT 持续研究任务。采集与日报发布分别验收，部分缺口不能
阻止日报按时交付，但必须说明实际覆盖范围。

午间仅接纳当日 11:29—11:30:59 的源时间，保存完整批次原始字节和 SHA-256。
盘中报价只作为完成日线的价格叠加，不能标成新完成日线；上午成交量不能和
上日全天成交量相除后称同时间放量。近期除权除息须在最终候选复核时另查，
历史接口首轮抓取本身并不能排除指标窗口内的机械除息缺口。

完整验收要求本期日期有经哈希核验的官方名录（当次刷新或同日已归档的官方来源），
代码集合一一对应、所有逐码状态有证据且
没有未解决缺口。技术覆盖和公司深研分别计数，不读取旧持续研究完成率。
同日归档复用时保留 `universe_fresh=false` 和刷新报错，另以 `universe_current`
标明当前日期的名录依据；前一日的缓存或种子不能冒充今日名录。

## 人工运行与验证

```bash
python -m unittest discover -s tests -p 'test_boll_*.py'
python -m market_screen.runner --phase auto --max-seconds 2400
```

`--import-history` 可导入以前留存的未复权原始证据，重新计算全部指标和哈希。
每次生成唯一不可变目录及分片，最新指针以日期和验收状态单调更新，新的不完整
运行不覆盖同日已经通过验收的完整结果。进程预算耗尽时保留逐股缓存和明确缺口，
下轮续跑；技术筛选未全量验收时退出码为 2。
